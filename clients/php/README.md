# orm — PHP client

The PHP executor: generated typed builders (`App\Orm\Battle`, …) over PDO (`pdo_mysql`,
`pdo_pgsql`, `pdo_sqlite`), with every statement compiled once by the `ormd` daemon and cached
(APCu across workers, an array per request). Version 0.0.1.

## Layout
- `src/` — the runtime, PSR-4 `Orm\` (`composer.json`). `Code.php` is generated by
  `ormgen errors --lang php` from `docs/errors.yaml`; do not edit it.
- `gen/` — the generated builders for `schema/schema.json`, namespace `App\Orm` by default
  (`ormgen gen --lang php --namespace ...`). Autoloading the generated namespace is the
  application's concern (add `"App\\Orm\\": "path/to/gen/"` to its own PSR-4 map); the
  runtime only needs `gen/bootstrap.php` required once — it registers the row classes and the
  schema hash the code was generated from.
- `tests/` — `integration.php` (the S1 demo statements plus the S3–S6 gates, on the database
  `ORM_TEST_DRIVER` / `ORM_TEST_DSN` name), `hostcodec.php` (the host AES/hex/ip stages against
  `tests/codec/aes-vectors.json`, byte for byte, no database needed), `compat.php`
  (PHP compatibility layer: 50 old-style/canonical pairs with identical IR and results, plus its error
  codes), the conformance runner lives in `tests/conformance/runner.php`, benches in `bench.php` /
  `bench_emulate.php`.
- `src/Compat.php` — the PHP `__call` compatibility layer (`CompatQuery` / `CompatWhere` traits the
  generated classes use); translation table in `docs/dsl.md` "PHP 호환층".

## ormd
PHP cannot link the engine, so the plans come from the compile daemon over a Unix socket:
`bin/ormd-0.0.1-<os>-<arch>` (built with `go build -o bin/ormd-0.0.1-$(go env GOOS)-$(go env GOARCH) ./cmd/ormd`).
Start it with the manifest the client was generated from:

    bin/ormd-0.0.1-darwin-arm64 -socket /run/orm/ormd.sock -schema /srv/app/schema/schema.json -dialect mysql

`-dialect` is `mysql` (default), `postgres` or `sqlite`: the plans are dialect text (docs/dialects.md).
`Orm::init` asks it once for the schema hash and the dialect (`{"op":"hash"}`) and refuses to start
when the hash differs from the generated code's (`SCHEMA_HASH_MISMATCH`) or the dialect differs
from the `Config` driver (`CONFIG`); nothing is watched or reloaded.

## Configuration
Either construct it in code:

```php
Orm::init(new Config(socket: '/run/orm/ormd.sock', schemaPath: '/srv/app/schema/schema.json', aesKey: 'secret'));
$db = Db::mysql('mysql:unix_socket=/tmp/mysql.sock;dbname=app;charset=utf8mb4', 'root', '');
// or, with ormd -dialect postgres / sqlite and Config(..., driver: 'postgres' | 'sqlite'):
$db = Db::postgres('pgsql:host=localhost;port=5432;dbname=app;user=app', null, 'secret');
$db = Db::sqlite('/srv/app/app.sqlite');   // PRAGMA busy_timeout=5000, journal_mode=WAL on open
```

or load `orm.toml` (`docs/config.md`) — `Orm::fromConfig('/srv/app/orm.toml')` returns the `Db`;
`[db].driver` (`mysql` default, `postgres`, `sqlite`) picks the constructor, and for `sqlite`
`[db].dsn` is the database file. Paths must be absolute, exist and not be symlinks; `[db].user`/
`password` apply only when the DSN names no user; `[debug].on_query = true` logs every statement
through `error_log`. `Db::driver()` tells which database a `Db` speaks; a `Db` of another driver
than the `Config` is `CONFIG`.

The `on_query` hook is `fn(string $sql, array $binds, float $seconds, string $planId, ?\Throwable $err)`:
secret binds read `"$SECRET"`, the SQLite `updated_ts` timestamp the executor binds reads `"$NOW"`
(so do `sql()` dumps), `$planId` is the plan cache key (16 hex digits, one per statement shape).

`Db::mysql` sets `PDO::ATTR_EMULATE_PREPARES = true` (decided by measurement, see
`Db::EMULATE_PREPARES`), so the DSN must carry `charset=utf8mb4` — the client-side quoting
uses the connection charset.

## PostgreSQL and SQLite (S6)
Same plans shape, dialect text (docs/dialects.md); what the PHP executor does differently:
- PostgreSQL plans carry `$n` placeholders. pdo_pgsql binds nothing to a `$n` it did not number
  itself, so the statement is prepared from its `?` form (the plan has one `$k` per bind slot in slot
  order); the hook, `sql()` and the statement cache keep the dialect text. A relation's `parent` slot
  expanded to N values renumbers every later `$k` (pow2 padding as everywhere).
- PDO sends untyped text to PostgreSQL; the column types the parameters. Booleans are bound as
  `PARAM_BOOL`, binary values (gz, raw AES, packed ip) as `PARAM_LOB` (bytea), the rest is inferred.
  A fragment must let the server infer a parameter's type: `CONCAT(x, ?)` (variadic "any") cannot
  be typed, `x || ?` or `?::text` can.
- SQLite binds ints as `PARAM_INT` (a text `'1'` never compares equal to `COUNT(*)`), bools as 0/1,
  and pads every datetime-shaped string (`YYYY-MM-DD HH:MM:SS[.f…]`) to six fraction digits, the
  canonical text form every executor writes and reads. `updated_ts` on UPDATE is the `now` slot
  (UTC, microseconds).
- Host stages: `bind_slots[].host_styles` (aes = MySQL key fold + AES-128-ECB/PKCS7 via openssl,
  hex upper-case, ip = INET6_ATON packing) are applied before binding; `columns[].styles` carrying
  them are decoded before the codec stages. `tests/codec/aes-vectors.json` is checked byte for byte.
- Rows: pdo_pgsql gives bool/int natively, numeric/jsonb/inet as text (cast by column type, as on
  MySQL), bytea as a stream the codec reads; pdo_sqlite gives INTEGER/REAL/TEXT/BLOB. Inserts read the
  id from `RETURNING`.
- A statement that failed is reset before it is reused (pdo_sqlite leaves it un-reset: rebinding would
  be SQLITE_MISUSE), and prepare errors reach the hook like execute errors (pdo_sqlite parses eagerly).

## Errors
`Orm\OrmException::$code_` is one of `Orm\Code::*`. Driver errors are passed through as
`PDOException` except, per driver: MySQL 1213 / SQLSTATE 40001 (`Code::DEADLOCK`, re-run by
`Db::transaction`) and 1062 (`Code::DUPLICATE_KEY`); PostgreSQL SQLSTATE 40P01 / 40001
(`DEADLOCK`) and 23505 (`DUPLICATE_KEY`); SQLite 5 / 6 busy/locked and their extended forms
(`DEADLOCK`, re-run) and the unique / primary-key constraint (`DUPLICATE_KEY`; pdo_sqlite reports
the primary code 19 with "UNIQUE constraint failed"). The driver message is kept.

## Tests
    go build -o bin/ormd ./cmd/ormd
    bin/ormd -socket "$PWD/bin/ormd.sock" -schema schema/schema.json &
    php -d apc.enable_cli=0 clients/php/tests/integration.php "$PWD/bin/ormd.sock" "$PWD/schema/schema.json"
    php -d apc.enable_cli=0 clients/php/tests/compat.php "$PWD/bin/ormd.sock" "$PWD/schema/schema.json"
    php -d apc.enable_cli=0 tests/conformance/runner.php "$PWD/bin/ormd.sock" "$PWD/schema/schema.json"

The tests connect with `ORM_MYSQL_DSN_PHP` when set (user `root`, no password), else
`mysql:unix_socket=/tmp/mysql.sock;dbname=orm_bench;charset=utf8mb4`. For the other databases start
ormd with `-dialect postgres|sqlite` and name the database (`ORM_TEST_DSN` is required, the tests
write rows; deploy/local-postgres.md for the local PostgreSQL, a copy of the seeded SQLite file):

    ORM_TEST_DRIVER=postgres ORM_TEST_DSN='pgsql:host=localhost;port=5432;dbname=orm_bench;user=maxkwon' \
      php -d apc.enable_cli=0 clients/php/tests/integration.php "$PWD/bin/ormd-postgres.sock" "$PWD/schema/schema.json"
    ORM_TEST_DRIVER=sqlite ORM_TEST_DSN="$PWD/bin/orm_bench.sqlite" \
      php -d apc.enable_cli=0 clients/php/tests/integration.php "$PWD/bin/ormd-sqlite.sock" "$PWD/schema/schema.json"
    php -d apc.enable_cli=0 tests/conformance/runner.php "$PWD/bin/ormd-postgres.sock" "$PWD/schema/schema.json" --driver postgres
    php -d apc.enable_cli=0 tests/conformance/runner.php "$PWD/bin/ormd-sqlite.sock" "$PWD/schema/schema.json" --driver sqlite --dsn "$PWD/bin/orm_bench.sqlite"
    php clients/php/tests/hostcodec.php

The runner's defaults are the Go runner's (`--dsn` overrides); its results equal
`tests/conformance/vectors.<dialect>.json` on every database, only `sql_dump` is dialect text.
