# S5 언어 레인 — 하드닝

main에는 `ormgen validate --dsn`, `ormgen import --dsn`, `ormgen errors --lang`, `docs/config.md`, `.github/workflows/ci.yml`이 구현되어 있다. 각 언어 레인은 다음 결과물을 제공한다. 규칙은 docs/lanes/s3.md §4를 적용한다.

## 1. 결과물
| 항목 | 내용 |
|---|---|
| 오류 상수 | `ormgen errors`가 생성한 Go, PHP, Rust 상수를 사용한다. MySQL 1213/SQLSTATE 40001은 `DEADLOCK`, 1062/23000은 `DUPLICATE_KEY`로 변환하고 driver 원문을 보존한다. |
| schema_hash 시작 검사 | client 초기화에서 생성 코드와 engine manifest의 hash를 한 번 비교한다. 불일치이면 `SCHEMA_HASH_MISMATCH`를 반환한다. 감시와 재로드는 사용하지 않는다. |
| runtime connection | 애플리케이션이 하나의 DSN URI와 runtime option을 주입한다. URI scheme이 database를 선택하며 runtime 설정 파일은 공개 연결 API에 포함하지 않는다. |
| on_query | `(sql, binds, duration, plan_id, err)`를 모든 언어에서 사용한다. secret bind는 `$SECRET`로 마스킹한다. |
| test DSN | integration test와 conformance runner는 지정된 환경 변수를 읽고 없으면 로컬 `/tmp/mysql.sock` 설정을 사용한다. |
| fixed cost | `examples/thin-slice`의 500회 측정으로 Go, PHP, Rust executor 비용을 기록한다. 목표는 native 대비 +5% 이하이다. |
| PHP 설정 | PK, 100행, 8개 IN 측정으로 `PDO::ATTR_EMULATE_PREPARES` 값을 정하고 JSON과 IP 결과를 검사한다. |
| 패키지 metadata | Go module, PHP composer, Rust Cargo metadata와 선언된 wasm 경로를 사용한다. symlink는 사용하지 않는다. |

## 2. 검증
기존 integration test와 runner가 계속 통과해야 한다. 시작 hash 오류, 상대 경로 `CONFIG`, 중복 key의 `DUPLICATE_KEY`를 각 client에서 검사한다. 이 단계에서는 새 conformance vector를 추가하지 않는다.
