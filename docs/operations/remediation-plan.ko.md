# 남은 작업의 진단과 해결 방안

[English](remediation-plan.md)

이 문서는 main `3a11004fb`와 함께 보고된 미병합 작업에서 확인한 남은 작업의 기술적 근거와 완료 판정 기준을 기록한다. 작업 원장이 아니라 설계 및 근거 지도다. 권위 있는 상태, 순서, 명령, 항목별 근거는 [실행 체크리스트](../plans/execution/checklist.ko.md)에만 있다. 현재 kit 표준 체크리스트와 겹치는 항목이 있다. 향후 하나로 통합할 때 모든 ID, 순서, 상태, 부모, 근거를 보존해야 한다. 이 문서로 상태를 추론하지 않는다. 아래의 완료 기준은 앞으로 필요한 근거이며, 과거 자료나 정적 분석은 실행 통과 결과가 아니다.

## 순서와 근거 원칙

1. 구현 전에 기존의 고유 작업을 보존한다. Collection 작업 `f2968adaf`(KSTD-5-82/83/84)는 전체를 통합한 뒤 동등한 변경과 깨끗한 작업 트리를 확인하고 작업 트리와 브랜치를 제거한다. 활성 T182-6 계획 수정, audit-lazy 커밋과 스테이징된 `db.c` 수정, API-34 단위 작업, delete-lock 동등성 변경, `17590acbe` blind-index source 작업 및 필요한 무시 파일 로그를 보존한다. 13개 변경 파일이 있는 catalog 작업 트리는 재구성 전에 인덱스와 1/2/3단계 blob을 저장한다. 진행 중인 merge나 cherry-pick은 없다. 오래된 tracked 트리 전체를 main 위에 복사하지 않는다. 작업 트리 제거 전에 `make worktree-remove`로 서버를 멈춘다. 공유 선언, 체크리스트, 변경 기록은 한 명이 순차 통합한다.
2. 확장 parity를 주장하기 전에 PHP 확장의 실제 native Model과 Collection 표면을 구현한다. T182-6은 실제 C 구현과 전용 실행 대상에 의존하며 PHP 사용자 영역 바인딩이나 Reflection만으로는 증거가 되지 않는다. 공통 공개 계약은 `Collection::getIterator(): Traversable`이며 확장은 native C `Iterator`를 제공한다. 순서가 있는 key, key type, value, model identity, lazy iteration, snapshot 동작, 반복 iteration, 수명/GC와 오류 의미를 유지한다. PHP 사용자 영역은 `yield` 구현을 계속 사용할 수 있다. `send`, `throw`, `getReturn`, `rewind` 같은 Generator 전용 동작은 공통 계약이 아니며 확장 iterator에 요구하지 않는다. PHP compile/eval, VM frame 합성, core handler 교체는 금지한다.
3. 소유 패키지에 native 테스트를 추가하고 연결한다. 단위 수용 기준은 정확히 선택된 테스트 이름이 실행되어 통과하는 것이다. 데이터베이스 기준은 여섯 클라이언트의 실제 출력과 상태가 MySQL, PostgreSQL, SQLite에서 요구된 결과를 내며, coverage 계약이 요구하는 곳에서는 결과와 상태가 두 번 동일해야 한다. 정적 선언 수, 코드 읽기, 과거 로그, 미실행 테스트는 진단 자료일 뿐이다. DB, 교차 클라이언트, 전체 빌드, feature-owner 및 전체 묶음 작업은 CI에서 검증한다. 이 계획 수행 중 로컬 DB나 넓은 테스트 묶음을 실행하지 않는다.
4. 독립 작업을 확장 의존성, parity, release gate보다 먼저 끝낸다. root가 독립 소스 파일 작업을 제한된 병렬로 할당/조정/검토하며, 공유 선언·체크리스트·changelog 통합자는 한 명으로 유지한다. 불가능성 제안은 상태를 바꾸기 전에 독립된 순차 감사를 거친다. 개발 중에는 선언에 따라 선택된 단위 case만 실행하며 `make owner-check`, 전체 client, 로컬 DB 검사는 실행하지 않는다. 체크리스트 상태를 바꾸기 전에 `make docs-check`를 실행한다. 변경 파일명을 읽는 test/script reader를 검색하고 정확한 명령과 수를 기록한다. 통과한 단위 근거와 영/한 changelog를 같은 커밋에 기록한다. 현재 release 묶음과 maintainer 전용 tag 규칙을 지킨다. 새 release를 제안하기 전에 원격 CI와 editor 산출물을 확인한다. 자동으로 release하거나 tag를 이동하지 않는다.
5. T237은 ORM worktree 종료 선언 누락을 기록한다. `make land`는 Makefile-origin 변수의 `WORKTREE_STOP`만 읽으므로 환경 변수나 command-line override는 종료 target을 등록하지 않는다. ORM Makefile에 `WORKTREE_STOP = orm-test-servers-stop`을 선언하고, Makefile에서 읽힌 값과 worktree 제거 전 stop target 실행, stop 실패 시 worktree와 data directory 보존을 focused fixture로 검증한다. KSTD-5-82 통합에서는 kit `make land`가 branch와 main 양쪽에서 `make build`를 자동 실행했고 둘 다 통과했다. 이는 저장소의 로컬 unit-only workflow를 넘으며 unit 근거가 아니다. `make land`를 unit-only라고 설명하지 않는다. full build를 피하면서 명시적 서버 종료, fast-forward 통합, 사용자 권한 범위의 정리를 보존하는 검증된 경로를 사용하거나 main에서 구현한다.

## 남은 항목 지도

같은 근거 가족의 행을 묶을 수 있지만 모든 ID를 명시한다. 완료 기준은 체크리스트 항목에 필요한 증거이며 이미 실행했다는 뜻이 아니다.

## 한계와 미해결 근거

T203 사용자 재현, T221-1의 Linux 과거 red, 현재 전체 parity, 실제 native 확장, 여섯 클라이언트 DB 결과는 근거 패킷에 없다. 완료 수용 조건으로 남는다. T182-6은 선언이나 class Reflection만으로 닫을 수 없다. 공개 반복 계약은 `Traversable`이며 native C `Iterator`가 ordered typed-key/value와 object identity, lazy snapshot iteration, 반복 iteration, 수명 및 오류 의미를 보존해야 한다. Generator 전용 method는 공통 계약에 포함하지 않으며 PHP 사용자 영역은 `yield` 구현을 계속 사용할 수 있다. 전체 CI 결과는 모든 group/target을 수집하고 setup 실패를 not-run으로 기록하며, 다음 실행 전에 원인 진단에 필요한 출력을 보존해야 한다. 이 문서를 추가해도 checklist 상태는 바뀌지 않는다. 구현 상태는 위의 unit 증거와 changelog 규칙에 따라 변경한다.
