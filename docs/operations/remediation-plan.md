# Remaining work: diagnosis and remedy

[한국어](remediation-plan.ko.md)

This document records the technical basis and intended acceptance for the remaining work identified on main `3a11004fb` and the unmerged work reported with it. It is a design and evidence map, not a task ledger. Under AGENTS.md, the [execution checklist](../plans/execution/checklist.md) is the sole ledger for item states, order, commands, and evidence. A kit standards checklist currently overlaps it; a future consolidation must preserve every ID, order, state, parent and evidence while leaving one ledger. No state is inferred from this document. “Acceptance” below describes evidence still required; evidence described as historical or static is not a passing execution result.

## Order and evidence rules

1. Preserve the existing unique work before implementation. Integrate the whole Collection work at `f2968adaf` (KSTD-5-82/83/84), then verify equivalent changes and a clean tree before removing its worktree and branch. Preserve the active T182-6 planning edits, audit-lazy commits and staged `db.c` correction, the API-34 unit work, the delete-lock parity changes, the blind-index source work at `17590acbe`, and needed ignored logs. For the catalog worktree with 13 dirty files, save the index and stages 1/2/3 before reconstruction; there is no merge or cherry-pick in progress. Do not copy an old tracked tree over main. Stop worktree servers with `make worktree-remove` before removal. Shared declarations, checklist and changelog edits have one serial integrator.
2. Establish the PHP extension's real native Model and Collection surface before claiming extension parity. T182-6's dependency is the actual C implementation and its focused target; PHP userland binding or Reflection alone is not evidence. The common public requirement is `Collection::getIterator(): Traversable`, with the extension providing a native C `Iterator`. Preserve ordered keys, key types, values, model identity, lazy iteration, snapshot behavior, repeat iteration and rewind, lifetime/GC and error behavior. PHP userland may continue to use `yield`; `send`, `throw`, `getReturn` and Generator's restriction on rewinding after iteration begins are not common guarantees. The native iterator must implement the required `Iterator::rewind()` behavior. Do not compile/eval PHP, synthesize VM frames, or replace core handlers.
3. Add and bind native tests with their owning packages. Unit acceptance means exact selected case names ran and passed. Database acceptance means each of six clients produced the required output and state on MySQL, PostgreSQL and SQLite, with two equal result/state runs where the coverage rules require it. Static declaration counts, source inspection, old logs, and tests not run are diagnosis only. Use CI for database, cross-client, full-build, feature-owner and suite work. Do not locally run databases or broad suites as part of this plan.
4. Complete independent work before dependent extension, parity and release checks. The root assigns, coordinates and reviews bounded parallel work on independent source files, with one serial integrator for shared declarations, checklists and changelogs. An impossibility proposal requires an independent sequential audit before any state change. During development, run only the declared selected unit cases, not `make owner-check`, a whole client or local DB checks. Run `make docs-check` before changing a checklist state. For a checklist item, search changed filenames for test/script readers, record exact commands and counts, then commit the passing unit evidence with its English/Korean changelog entry in the same commit. Keep the existing release batch and maintainer-only tag rules. Audit existing remote CI and editor artifacts before proposing any new release; never retag or bump automatically.
5. T237 records the missing ORM worktree stop declaration: `make land` reads `WORKTREE_STOP` from a Makefile-origin variable, so an environment or command-line override does not register the target. Add `WORKTREE_STOP = orm-test-servers-stop` to the ORM Makefile and verify with a focused fixture that the variable is read from the Makefile, the stop target runs before worktree removal, and a stop failure preserves the worktree and its data directory. The KSTD-5-82 landing also showed that kit `make land` automatically runs `make build` on both the branch and main (both passed); this exceeds the repository's local unit-only workflow and is not unit evidence. Do not describe `make land` as unit-only. Prefer implementing on main or use a verified integration route that avoids the full build while preserving explicit server shutdown, fast-forward integration, and cleanup under the user's authorization.
