# S7: Additional Features and Documentation

Status: not started.

This document is the English page for S7. The Korean translation is [S7 한국어 문서](ko/s7.md). The feature list and the documentation list use the same item identifiers.

## Feature work

| ID | Work | Completion condition |
|---|---|---|
| T7.1 | protobuf/Connect transport | Go, PHP, and Rust use the same message definitions and conformance vectors. |
| T7.2 | FrankenPHP in-process path | The path is implemented only if the three-language execution rules remain unchanged and benchmark data is recorded. |
| T7.3 | DDL diff and migration generation | The generator produces deterministic output and rejects destructive changes without an explicit option. |
| T7.4 | Multi-tenant `scope` | Schema, IR, generated APIs, errors, and database tests are defined for all supported clients. |
| T7.5 | `point`, `yaml`, and `curlfile` styles | Encoding and decoding vectors produce the same values in all supported clients. |
| T7.6 | Server streaming | Stream lifecycle, cancellation, errors, and row ownership are specified and tested. |
| T7.7 | `ormgen precompile` | Static query shapes can be generated, loaded, and verified against the schema hash. |
| T7.8 | Fourth language client | The client passes the common structure, symbol, state, and conformance checks. |
| T7.9 | `mysql_async` comparison | Rust driver results and benchmark data are recorded against the current driver. |
| T7.10 | `multi_statement` plan | Relation stages produce the same results and statement counts in single and multi-statement modes. |
| T7.11 | Typed scan optimization | Go and PHP benchmarks meet the documented target or the target is revised with measured evidence. |
| T7.12 | 150-table Rust fixture | The fixture is stored or generated deterministically and the compile-time result is recorded. |

## Documentation work

| ID | Work | Completion condition |
|---|---|---|
| T7.D1 | Language file structure | English Markdown files under `docs/` are the source documents. |
| T7.D2 | Korean translations | Korean files under `docs/ko/` contain the same headings, code samples, tables, and links. |
| T7.D3 | Language navigation | Pages provide links between the English page and Korean translation. |
| T7.D4 | Style review | Informal, figurative, personifying, and ambiguous wording is removed from manuals. |
| T7.D5 | Feature tables | Each feature documents inputs, outputs, errors, state changes, and supported clients. |
| T7.D6 | Unfinished work list | Unimplemented features are marked as not started or partial. |
| T7.D7 | Translation checker | CI compares document headings, code fences, tables, and link targets. |
| T7.D8 | Style checker | CI rejects configured informal and figurative expressions. |
| T7.D9 | Examples and commands | Each completed S7 feature has examples and reproducible verification commands. |
| T7.D10 | Pages publication | The static build contains both language paths and passes link and no-JavaScript checks. |

## Common completion rule

An S7 item is complete only when implementation, tests, documentation, and static publication are complete. A feature that cannot use the same logical structure in Go, PHP, and Rust remains unimplemented.
