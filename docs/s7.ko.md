## 공통 완료 조건

S7 항목은 구현·테스트·문서·정적 게시를 모두 완료해야 닫는다. Go·PHP·Rust·TypeScript에서 같은 논리 구조를 사용할 수 없는 기능은 구현하지 않는다.

FrankenPHP in-process 실행은 PHP 런타임 전용 최적화이며 공통 API와 자료 구조가 없으므로 S7에서 제외한다.

## T7.3 마이그레이션 명령

```sh
go run ./cmd/ormgen diff \
  --from old-schema.json \
  --to schema/schema.json \
  --dialect mysql \
  --out migration.sql
```

이 명령은 파괴 옵션 없이 `ADD COLUMN`과 신규 테이블 SQL을 생성한다. 테이블 삭제, 컬럼 삭제, 컬럼 정의 변경이 있으면 실패한다. 파괴 SQL을 검토한 경우에만 `--allow-destructive`를 추가한다.

## T7.7 precompile 명령

```sh
go run ./cmd/ormgen precompile \
  --schema schema/schema.json \
  --dialect mysql \
  --in request.json \
  --out plan.json
```

출력에는 `version`, `schema_hash`, `dialect`, `request_sha256`, `plan`이 포함된다. 클라이언트는 plan을 로드하기 전에 `schema_hash`를 비교한다.

컴파일러 wire 정의는 `proto/orm/compiler/v1/compiler.proto`다. 전체 request tree, tenant scope parameter, write field, assembly tree, bind metadata, compiler 오류, server metadata를 포함한다. `scripts/proto/generate.sh`는 버전을 고정한 plugin으로 Go·PHP·Rust·TypeScript message type을 생성한다. `ormd -listen 127.0.0.1:8080 -schema schema/schema.json`은 Connect unary 경로에서 binary Protobuf를 처리한다. `make proto-check`는 server를 시작하고 네 `CompilerTransport` 구현이 동일한 metadata와 plan을 반환하는지 검사한다. 네 executor는 plan cache miss에 이 전송을 사용하며 MySQL·PostgreSQL·SQLite 데이터베이스 벡터 58개를 통과한다.

## T7.4 scope 지시문

```text
%% scope battle service_seq
```

지시문은 존재하는 NULL 불가 정수·문자열·enum 컬럼을 요구한다. 생성 클라이언트는 query 객체에만 `scope(value)`를 제공한다. request는 parameter index를 사용자 predicate tree와 분리된 `query.scope_p`에 저장한다.

| 동작 | Scope 처리 |
|---|---|
| root select, update, delete | 전체 사용자 WHERE group 외부에 scope 조건을 추가한다. |
| join | LEFT JOIN을 포함한 JOIN ON에 join entity의 scope를 추가한다. |
| relation | relation query WHERE에 child scope를 추가한다. |
| insert | 선언된 scope 컬럼과 scope parameter를 추가한다. 명시적인 대입은 같은 parameter index를 사용해야 한다. |
| update와 upsert | 선언된 scope 컬럼 대입을 거부한다. |
| raw SQL | compiler가 안전한 삽입 위치를 결정할 수 없으므로 scoped request를 거부한다. |

`%% scope`가 없는 entity에서 `scope(value)`를 호출하면 `IR_INVALID`를 반환한다. update와 delete에는 명시적인 사용자 WHERE group이 계속 필요하다. 단위 테스트는 OR 우선순위, join ON 위치, relation 단계, 쓰기 제한, 잘못된 request를 검사한다. 물리 테스트는 네 클라이언트에서 MySQL·PostgreSQL·SQLite의 tenant 분리를 검사한다.

AES 컬럼은 NULL 불가 정수 `aes_key_version` 컬럼을 요구한다. 버전 컬럼은 평문 메타데이터이며 인코딩 스타일을 가질 수 없고 기본 projection에서 제외한다. 회전 쿼리만 버전 컬럼을 명시적으로 조회한다. `npm run schema:check`는 이 규칙을 검사하고 schema builder도 `schema.json` 기록 전에 적용한다. Go는 버전별 키 목록과 한 행의 모든 AES 컬럼을 재암호화하는 함수를 제공한다. 모든 AES 컬럼 처리가 성공하기 전에는 입력 행을 변경하지 않는다. 호출자는 반환된 AES 컬럼과 버전을 하나의 트랜잭션으로 저장해야 한다. 데이터베이스 행 순회, 상태 조회, PHP·Rust·TypeScript API는 T7.13 잔여 작업이다.

```go
keyring, err := orm.NewAESKeyring(map[int32]string{1: oldKey, 2: newKey}, 2)
rotated, err := orm.RotateAESRow(row, "aes_key_version", columns, 2, keyring)
```

## T7.5 추가 코덱

Go·PHP·Rust·TypeScript에 재귀 `curlfile` 값, 엄격한 YAML 1.2 파싱, `point` 변환을 구현한다. 네 클라이언트는 데이터베이스 출력 `(x,y)`와 전송 텍스트 `POINT(x y)`를 입력받고 유한한 좌표 두 개를 요구한다. 생성 필드는 [ir-v1.ko.md](ir-v1.ko.md)의 타입을 사용한다. MySQL과 SQLite에는 `POINT(x y)`를 bind하고 PostgreSQL에는 native text `(x,y)`를 bind한다. MySQL은 `ST_PointFromText`와 `ST_AsText`를 사용하고 PostgreSQL은 text를 거쳐 point로 변환하며 SQLite는 text를 저장한다. 단위 테스트는 생성 타입, SQL plan, 잘못된 값, 실제 SQLite 데이터베이스를 검사한다. 컨테이너 테스트는 실제 MySQL과 PostgreSQL을 검사한다.

## T7.8 TypeScript 구조 검사

TypeScript 모듈은 `npm run typescript:build`로 빌드하며 `dist/index.js`와 `dist/index.d.ts`를 export한다. `clients/typescript/src/index.ts`에 공통 request, query, where, row, compiler, executor 타입을 정의한다. 생성 진입점은 `battle`, `user`, `service`, `service_module`, `service_member`를 포함하며 선언되지 않은 엔티티에서 `scope()`를 호출하면 오류를 반환한다. `Db.fromConfig()`는 생성 schema hash, `orm.toml` 필드, 선언 경로, Connect metadata, driver, AES 요구사항을 검사한다. `npm run typescript:check`는 TypeScript 컴파일러를 실행하고 `node tests/typescript/check.mjs`는 선언과 메서드 순서를 검사한다. 코덱 벡터와 데이터베이스 벡터 58개가 MySQL·PostgreSQL·SQLite에서 통과한다.

## T7.15 마이그레이션 복구

`ormgen recover`는 검토한 구조화 plan 또는 `ormgen migrate`가 기록한 migration ID를
입력으로 받는다. 데이터베이스 마이그레이션 잠금을 획득한 뒤 이력 상태와 실제 schema를
조회한다. 실제 DB가 도착 schema와 일치하면 `applied`, 출발 schema와 일치하면 `retryable`을
기록한다. 그 외 상태는 이력과 파일 로그를 변경하지 않고 `MIGRATION_RECOVERY_UNSAFE`를
반환한다. MySQL·PostgreSQL·SQLite에 같은 상태 전이를 적용한다. 명령 형식과 결과 표는
[usage.ko.md](usage.ko.md)에 있다.

## T7.17 마이그레이션 입력

DDL, diff, plan, migrate, verify, apply, recover는 공통 loader로 schema 입력을 처리한다. 입력은 Mermaid 파일, manifest JSON 파일, ORM 생성 SQL 파일, `db:<dsn>`이다. `ormgen ddl`과 `ormgen diff`가 생성한 SQL은 결정적인 `orm-schema-v1` metadata를 포함한다. loader는 사용 전에 embedded manifest hash를 검사한다. 이 metadata가 없는 SQL은 scope, codec style, named predicate, relation option을 표현할 수 없으므로 `MIGRATION_SOURCE_LOSS`를 반환한다. 구조화 plan은 검증된 정방향·rollback 작업을 포함한다. `ormgen rollback`은 실행 전에 plan, history, 실제 target schema, destructive 위험 승인을 검사하고, 실행 후 source schema와 파일 로그를 검증한다. 명령 행렬과 예제는 [usage.ko.md](usage.ko.md)에 있다.
