# S7: 추가 기능과 문서 정비

상태: 미착수.

이 문서는 [영어 문서](s7.md)의 한국어 문서다. 기능 목록과 문서 목록은 같은 항목 ID를 사용한다.

## 기능 개발

| ID | 작업 | 완료 조건 |
|---|---|---|
| T7.1 | protobuf/Connect 전송 | Go·PHP·Rust·TypeScript가 같은 typed 메시지 정의와 적합성 벡터를 사용한다. |
| T7.3 | DDL diff와 마이그레이션 생성 | 결정적 결과를 생성하고 명시적 옵션 없이 파괴적 변경을 거부한다. |
| T7.4 | 멀티테넌시 `scope` | 지원 클라이언트 전체에 스키마·IR·생성 API·오류·DB 테스트를 정의한다. |
| T7.5 | `point`, `yaml`, `curlfile` 스타일 | 지원 클라이언트 전체에서 인코딩·디코딩 결과를 비교한다. |
| T7.6 | 서버 스트리밍 | 스트림 수명·취소·오류·행 소유권을 정의하고 검사한다. |
| T7.7 | `ormgen precompile` | 정적 쿼리 형태를 생성·로드하고 스키마 해시를 검사한다. |
| T7.8 | 네 번째 언어 클라이언트 | 공통 구조·심볼·상태·적합성 검사를 통과한다. |
| T7.9 | `mysql_async` 비교 | 현행 Rust 드라이버와 결과·성능 자료를 비교 기록한다. |
| T7.10 | `multi_statement` 플랜 | 단일 문장과 다중 문장에서 관계 결과와 문장 수가 일치한다. |
| T7.11 | typed 스캔 최적화 | Go·PHP 성능이 문서 기준을 충족하거나 측정 자료로 기준을 변경한다. |
| T7.12 | 150테이블 Rust fixture | fixture와 컴파일 결과를 저장하거나 결정적으로 생성한다. |
| T7.13 | AES 키 로테이션 | AES 테이블에 `aes_key_version`을 사용하고 모든 지원 클라이언트에서 조회·저장·상태 조회·재암호화를 검사한다. |

## 공통 완료 조건

S7 항목은 구현·테스트·문서·정적 게시를 모두 완료해야 닫는다. Go·PHP·Rust·TypeScript에서 같은 논리 구조를 사용할 수 없는 기능은 구현하지 않는다.

FrankenPHP in-process 실행은 PHP 런타임 전용 최적화이며 공통 API와 자료 구조가 없으므로 S7에서 제외한다.
