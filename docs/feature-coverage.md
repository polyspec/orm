# Feature coverage verification

Each feature in `contracts/features.json` declares `coverage.kind`, `coverage.cases`, `coverage.owners`, and `coverage.dependents`. Use `database` when behavior reads or changes a database and `independent` otherwise. Every `pass` or `partial` client declares one owner under `clients/<language>` with `part`, `tests`, and a command for each required database (`mysql`, `postgres`, `sqlite`) or the single `none` slot. `dependents` is an explicit array; each dependent part declares its own nonempty cases, tests, and commands. A missing owner, dependent declaration, test, or command fails `make feature-check`. Owner tests must reside under their client part; dependent tests must reside under their dependent part. The checker rejects paths outside a part and symbolic paths. Commands execute from the declared part directory.

A command executes its cases once against the current environment and writes only one JSON report to standard output. The checker runs each command twice. Each report contains `feature`, `role` (`owner` or `dependent`), `part`, `tests`, `language`, `database`, `success: true`, `cases`, and `results`, an array with exactly one `{ "id": "case-id", "value_json": "..." }` result per declared case ID. A dependent report also names its `dependent` ID. `value_json` preserves the exact serialized value, including numbers outside binary64 precision. A database command also reports nonempty `state_before` and `state_after` digests calculated from the observed database state. The checker requires equal digests within and across runs and compares both result arrays. It limits each command to ten minutes and rejects an unsuccessful exit or malformed report. Diagnostic text goes to standard error. It does not read saved reports.

The test cases under `scripts/features/coverage.test.mjs` change one required dimension at a time and require failure for an absent owner, dependent, test path, client, database, case, repeated run, state comparison, or an undeclared result. Current feature declarations do not yet supply these commands, so `make feature-check` fails until every claimed behavior has current execution evidence. A successful checker self-test does not assert that client behavior is complete.
