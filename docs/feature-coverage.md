# Feature coverage verification

Each feature in `contracts/features.json` declares `coverage.kind`, distinct `coverage.cases`, `coverage.owners`, and `coverage.consumers`. Use `database` when behavior reads or changes a database and `independent` otherwise. Every `pass` or `partial` client declares an owner under `clients/<language>` with `part`, `tests`, and native test commands for each required database (`mysql`, `postgres`, `sqlite`) or the single `none` slot. Each consuming part declares separate cases and tests in its own directory. Missing declarations and paths outside the declared part fail `make feature-check`.

Each database slot contains an array of command objects with `runner` (`node`, `php`, `go`, or `cargo`), `test` (an exact path in `tests`), and distinct `cases`. Every declared test and case must occur exactly once. A database command also names `dsn_env`, a required environment variable containing the database URI. The checker rejects shell strings and extra command fields. It invokes Node and PHP test files with the declared case IDs as arguments; these tests print `CASE <id> PASS` only after their assertions pass. Go uses `go test -json` with an anchored case filter; Rust uses `cargo test` with an exact case filter. The checker requires a successful process exit and an observed pass event for every declared case. Test output cannot supply a success report.

For each database run, the checker invokes its state reader against the same URI immediately before and after the tests. It records the state digest itself; test output cannot provide it. Each set of tests runs twice under a ten-minute deadline per process. Both runs must observe exactly the declared cases and equal results; database state must remain equal before and after each run and across runs. Missing environments, test events, database tables, or state reads fail. The checker never reads a saved report.

The test cases under `scripts/features/coverage.test.mjs` change one required dimension at a time and require failure for invented JSON success, an absent owner, consumer, test path, client, database, case, repeated run, state comparison, or an undeclared result. Current feature declarations do not yet supply these commands, so `make feature-check` fails until every claimed behavior has current execution evidence. A successful checker self-test does not assert that client behavior is complete.
