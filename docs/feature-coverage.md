# Feature coverage verification

Each feature in `contracts/features.json` declares `coverage.kind`, distinct `coverage.cases`, `coverage.owners`, and `coverage.dependents`. Use `database` when behavior reads or changes a database and `independent` otherwise. Every `pass` or `partial` client declares an owner under `clients/<language>` with `part`, `tests`, and native test commands for each required database (`mysql`, `postgres`, `sqlite`) or the single `none` slot. Each dependent part declares separate cases and tests in its own directory. Missing declarations and paths outside the declared part fail `make feature-check`.

Each database slot contains an array of command objects with `runner` (`node`, `php`, `go`, or `cargo`), `test` (an exact path in `tests`), and distinct `cases`. Every declared test and case must occur exactly once. A database command also names `dsn_env`, a required environment variable containing the database URI. The checker rejects shell strings and extra command fields. It invokes Node and PHP test files with the declared case IDs as arguments; these tests print `CASE <id> PASS` only after their assertions pass. Go uses `go test -json` with an anchored case filter; Rust uses `cargo test` with an exact case filter. The checker requires a successful process exit and an observed pass event for every declared case. Test output cannot supply a success report.
For Go and Rust, `symbols` maps each shared case ID to the exact native test name in the declared source file. The checker rejects missing, extra, or duplicate symbol names and verifies each native pass event before recording the shared ID. Node and PHP use the shared ID directly. Database commands run with `ORM_FEATURE_DATABASE` and `ORM_FEATURE_DSN` set to the selected database and declared URI; a missing URI fails before the test starts.

For each database run, the checker invokes its state reader against the same URI immediately before and after the tests. It records the state digest itself; test output cannot provide it. Each set of tests runs twice under a ten-minute deadline per process. Both runs must observe exactly the declared cases and equal results; database state must remain equal before and after each run and across runs. Missing environments, test events, database tables, or state reads fail. The checker never reads a saved report.

The test cases under `scripts/features/coverage.test.mjs` change one required dimension at a time and require failure for invented JSON success, an absent owner, dependent part, test path, client, database, case, repeated run, state comparison, or an undeclared result. `make feature-check` fails until every claimed behavior has current execution evidence. A successful checker self-test does not assert that client behavior is complete.
`make feature-coverage` runs the coverage of every feature once, as `make check` does, and `make feature-check` runs it with every verification command. `node scripts/features/coverage.mjs --feature <id>`, under the test environment of `.runtime/servers/env`, runs the coverage specs of that feature only: its owners and dependent parts on each database, twice. `<id>` is a feature `id` of `contracts/features.json`, as for `scripts/features/check.mjs --feature`; an unknown id fails with the list of valid ids instead of running nothing. For example, `node scripts/features/coverage.mjs --feature dsn_connection` executes only the DSN connection feature. The DSN feature uses read-only owner cases in all four clients and generated-model dependent cases in the Go and Rust client parts on each database. The selected URI is supplied through `ORM_FEATURE_DSN`; the checker reads database state before and after both runs.

## Owner checks

`make owner-check` runs the checks that own the changed files: by default the files that differ from `HEAD` and the untracked files, or the files given as `PATHS="<paths>"`. Every verification command of `contracts/features.json` declares its `inputs`, and every coverage part, an owner client (`owner/<language>`) or a dependent part (`dependent/<id>`), declares its `tests` and optional `inputs`. `scripts/features/owners.mjs` selects the commands and parts whose inputs contain a changed file or whose declared fixture data (a JSON or dbspec file) names one, as `contracts/fixtures/schema_definition.json` names `contracts/fixtures/audit.dbs` and `contracts/symbols/rust.json` names the Rust sources; a file named by a named file is not followed. It prints each selected command and part with the paths that selected it, and each changed path that selects nothing. A helper that several features use, such as the coverage runner `clients/php/tests/coverage_cases.php`, is declared under `helpers` with its own check and is an input of nothing: its change runs only that check (`scripts/features/check.mjs --run --helper <id>`), and `make check` runs every feature that uses it. A change to `contracts/features.json` selects the commands and parts of every feature whose entry differs from `HEAD`, and every helper whose entry differs; a change outside these entries selects none, as `make check` runs every feature. The selected commands run as `scripts/features/check.mjs --run --feature <id> --command <id>` and the selected parts as `scripts/features/coverage.mjs --feature <id> --part <part>`, each as one step with RUN, PASS or FAIL and its elapsed time; the deadlines are those of the cases inside the step. The declaration check fails on a verification command without inputs, an input that matches no tracked file and a helper declared as an input. It also runs the make targets that `contracts/check-inputs.json` declares with scope `owner` and whose inputs match a changed path; a target with scope `suite`, such as `client-db-check` or `feature-check`, runs only in `make check`, and a target without a scope fails the selection. `node scripts/features/owners.mjs --list [<paths>]` prints the selection without running it. `scripts/features/owners.test.mjs` runs in `make feature-unit-check`.
